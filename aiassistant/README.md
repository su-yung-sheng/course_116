## 〇、目前狀態：🔓 暫時全部開放（2026-10-10）

- **不用登入、不填個人資料**（`config.js` 的 `NO_LOGIN: true`）：大家用同一份「訪客」紀錄，只存在這台電腦的瀏覽器（`aia-aia1-progress-guest-00`）；電腦教室有還原卡的話重開機就清掉。頁面最下面有「🗑 清除這台電腦的紀錄，重新開始」。
- **六關都可以直接點進去**：關卡 3 的骨架卡不再要求關卡 2 的規格卡先過助教（只提醒）。每張卡送進 Canvas 前「先給助教檢核、寫預測」的流程不變（這是教學設計，不是鎖關）。
- 之後要記名、接教師端時，把 `NO_LOGIN` 改成 `false`，會恢復班級座號姓名登入。

## 一、主軸

**用 AI 協助自己設計 AI。** 第 1～2 節，每個學生請 Gemini 幫忙起草一位自己的「進度檢核助教」（Gemini App 的「技能」），用測試題考它、修正它；
第 3～6 節用 Gemini Canvas 做遊戲，**每一張卡送進 Canvas 前都先給自己的助教檢核**（取代原本同學互審）。助教判錯了，學生回頭改助教的指令，助教跟著遊戲一起改版。

- 個人製作（不是兩人一組）、學校 Google 帳號。
- 助教用 **Gemini App 的技能**，不用 Gem：Google 公告教育版的 Gem 最快 2027-06-01 停用（本課 2028 年春天上）。Gemini App 的技能所有年齡可用；Workspace（文件、試算表裡）的技能限 18 歲以上。
- Canvas：未滿 18 歲不能在 App 裡「加入 Gemini 功能」，所以遊戲不接 AI；作品用「分享到 Classroom」繳交。

## 三、引導機制（為什麼不是自由聊天）

- **卡片**：學生只能送網站產生的卡（起草卡 H1、修正卡、骨架卡 A、讀懂卡 B、功能卡 C、除錯卡 D、說明卡 E），卡片內容由表單自動組成。每張卡第一行是【卡片名稱】，助教靠它判斷卡種。
- **🚦 檢核閘門**（`gate()`）：① 複製給助教（不扣能量）→ 貼回助教的最後一行「結論：通過／不通過」→ ② 寫預測 → ③ 送進 Canvas（⚡−1）→ ④ 實際上＋過驗收？
  - 卡片在助教通過後又改過 → 要重新檢核。
  - 「🙋 我認為助教判錯了」→ 寫理由、記進助教錯誤紀錄，可以先繼續（學生決定，不是 AI 決定）。
- **⚡ 能量**：每節 6 點，送一張卡進 Canvas（或 H1、修正卡、E 給 Gemini）扣 1；問助教、卡 B、手動關不扣。用完要找老師（老師確認碼 +2）。
- **🙋 求救**：寫進 `live.help`，教師端接上後可以看到誰在等、等了幾分鐘；學生端先顯示「等待時可以先做什麼」。
- **老師確認碼**：L4～L6 的 ⭐⭐⭐、補充能量。`config.js` 的 `AIAIDE.TEACHER_HASH` 存 SHA-256('c116-aiaide:' + 確認碼)；換碼：在 index.html 按 F12 輸入 `AIAIDE.hash('新碼').then(console.log)`。**不要把確認碼本身寫進 repo。**
  ⚠️ 和本機進度一樣只是學習回饋：會寫程式的學生還是可以猜碼，成績以老師在教室看到的為準。

## 四、資料（形狀和主系統的進度文件一樣，但分開存）

本機版存在瀏覽器的 `aia-profile`（登入）、`aia-{TERM}-progress-{班級}-{座號}`（進度）；和闖關網站的 `c116-…` 分開。

```
aiassistant-progress/{學號} = { modules: { aiaide: {
  levels: { L1～L6: { stars, extra: { 表單欄位…, g_A: { aide, aideFor, ov, pred, sent, act, ok }, energy, steps: [], tOk } } },
  aide:   { versions: [{ v, lv, text, why: [], at }], errors: [{ lv, card, said, think, at }] },
  log:    [{ lv, card, text, aide, pred, act, ok, at }],      // 提示詞紀錄，最多 200 筆
  live:   { lv, step, help, helpAt, at }                       // 誰在哪一關、哪一步、有沒有在求救
} } }
```

- 關卡資料用 `STORE.saveLevel`（星星只增不減）；`aide`／`log`／`live` 用 `STORE.modData(mod, key, value)`（這個資料夾的 `store.js` 才有）。
- 不存 Gemini 的對話全文：只存學生自己填的、和助教回覆的最後一行（結論）。助教指令全文每版最多 4000 字。

## 五、教師後端（設計，第二階段和主系統一起做）

和主系統用**同一個 Firebase 專案**（同一套 Google 登入、名冊），但用**自己的集合**：主系統接好 Firestore（docs/02「正式上課前」）後，把這個資料夾的 `store.js` 照主系統的寫法改寫：

1. `saveLevel`／`modData` → Firestore `merge` 寫入 `aiassistant-progress/{學號}`。
2. `live` 另外寫一份到 `aiassistant-live/{學號}`（小文件、教師端用 `onSnapshot` 即時監聽，不必每次讀整份進度）；規則：學生只能寫自己的、老師可以讀全班。
3. 新增 `aiassistant/teacher.html`（登入、名冊沿用主系統）：
   - **全班總覽**：座號 × L1～L6 星星、目前關卡與步驟、剩餘能量、助教版本；🙋 求救的人排最上面，顯示等了幾分鐘，老師按「處理了」把 `help` 改回 false。
   - **個人明細**：提示詞紀錄、助教各版指令對照（標出改了哪一句）、T1～T6 結果、助教錯誤紀錄。
   - **老師確認**：在教師端直接核可 L4～L6 的 ⭐⭐⭐（取代現在的確認碼，寫入 `tOk`）、輸入隱藏測資結果。
   - **異常旗標**：一節送出超過 6 次、連續送出一模一樣的卡、一直按「助教判錯」、`tOk` 不是老師寫的。
   - **匯出**：CSV（和其他單元同一張成績表）。
4. 在那之前：本機版（電腦教室有還原卡會被清掉）。若要在第二階段之前上課，比照 pylab 先用 GAS 試算表存同一份資料形狀。
