# 05 安全性：答案只在伺服器

> 目標：學生按 F12（開發人員工具）翻原始碼、網路請求、`window` 變數，或裝 Tampermonkey 之類的使用者腳本，**都拿不到答案**；
> 星星由伺服器發、附簽章收據，改自己電腦裡的紀錄騙不了老師。
>
> 2026-09-28 起改成**伺服器驗證**（Google Apps Script）。以前的「前端封存」（`shared/seal.js`：雜湊＋AES-GCM）已經整個移除 ——
> 封存擋得住「看答案」，擋不住「在自己電腦上一個一個試開」；只有答案不在學生電腦上，才真的擋得住。

## 一、架構

```
private/（明碼，只在老師電腦）
   │  node tools/build.mjs
   ├──► 公開網站（GitHub Pages）：{學期}/content/*.js ── 只有題目
   └──► private/server/ ──► 貼到 Google Apps Script（網頁應用程式）
                              server/*.js（程式，公開在 repo）＋ 90_answers.js（全部答案，只在 Apps Script）

學生的瀏覽器 ──「我選了什麼」──► Apps Script：判斷對錯、扣 ❤️、出題、發星星（HMAC 簽章收據）
             ◄──「對／錯、提示、解說」──
```

| 內容 | 網頁拿到什麼 | 伺服器做什麼 |
|---|---|---|
| 分類題 sort | 卡片文字、選項 | 比對正解；答錯扣 ❤️；答對才回傳解說 |
| 排序題 order | 打亂的項目 | 一步一步比對 |
| 組合題 build | 零件、客人需求的文字 | 照客人的規則（預算、屬性）檢查 |
| 打字題 type | 題目、提示 | 比對（全形轉半形、去空白、不分大小寫） |
| 🎲 隨機出題 | 題目文字、選項（依序點的題目，選項**不帶 id**） | 用種子產生題目、驗證時重新產生同一題再檢查；分層提示、追問「為什麼」 |
| 🧪 實驗站 | 畫面要用的情境（`pub`） | 隱藏的資訊留在伺服器（`sec`）：例如封包哪幾號會遺失、翻頁動畫的真正順序、急診室哪個程式是系統程式、嵌入式的規格數值 |
| 試算表 | 題目、資料 | 用同一份試算表引擎重算學生的公式；清理後的資料、標準答案、提示、延伸說明都在伺服器 |
| Python | 題目、範例、公開測資的輸入 | 評分時才給全部測資的輸入；學生瀏覽器跑出的**輸出**送上來比對；隱藏測資的說明、提示都在伺服器 |
| Python 三段式（第 1、2 題） | 題目、黑框示範、完成條件 | 檢查規則（`server/54_pystep.js`）、線索；學生執行一次後把程式碼和執行過程送上來，伺服器檢查完成條件與情境內容、發星（附收據） |
| 5016B 專題 | 題目、選項 | 一節一局：比對預測、回傳解說、記錄錯幾次；全部說對才發星（沒錯 3⭐、錯 1 次 2⭐、錯 2 次以上 1⭐）；S5 成果卡填完整 3⭐ |
| 單元一 快速檢核 | 按鈕文字（`data-k` 已拿掉） | 一課一局（`dqs → dq → dqf`，2026-10-03 起）：比對、回傳提示、記錯幾次；三題都答對才發星（沒錯 3⭐、錯 1 次 2⭐、錯 2 次以上 1⭐，附收據） |
| 🐍 pylab 學生版 | 題目、公開測資輸入；各關星數＝🔑 進度碼（前 4 碼公開、後 8 碼簽章） | ☁️ 各學生星數存在出題老師的試算表（班級＋座號）；評分前照雲端紀錄＋進度碼檢查上一關 2⭐（伺服器端鎖關），評完存雲端、發新進度碼；`pcv` 驗證成績卡；`plt` 老師密碼看進度表 |

**計星**：每一局（run）存在伺服器（CacheService，6 小時）。❤️ 由伺服器扣；`fin`（結算）時伺服器逐回合檢查「每一題都答對了」才發星，星星附 **HMAC-SHA256 收據**
（`學期|班|號|姓名|單元|關卡|星|時間`，金鑰是 Apps Script 的指令碼屬性 `SECRET`）。收據存在學生的進度裡（`rc`、`ts`），教師端可以驗證這顆星是伺服器發的。

**同時很多人送出**：讀寫同一局用 LockService 排隊，不能「同時送出好幾個答案」繞過 ❤️；伺服器忙時網頁會自動等一下再送（最多 3 次）。

## 二、連不上伺服器：練習模式

沒網路、學校擋掉 Google、伺服器還沒部署（`VERIFY_URL` 留空）→ 網頁自動進入 **📴 練習模式**：

- 互動遊戲：可以看題目、作答，但**不判斷對錯、不記星**；🎲 出題器和 🧪 實驗站的回合要連線（可以跳過）。
- 試算表：可以寫公式、看算出來的值，不判斷；資料清理的步驟要連線。
- Python：只跑公開的範例測資給學生看輸出，不判斷、不記星。
- 5016B、單元一：模擬器照跑，只是沒辦法判斷預測。

## 三、還擋不住的事（誠實說明）

1. **跨局硬試**：學生身分沒有登入驗證（只填班級座號），理論上可以寫程式一直開新局、每局用 3 顆 ❤️ 試選項。代價：每次都要打伺服器、選項多的題目試不完、🎲 題目每次不一樣；教師端之後可以用「逐題紀錄」標出異常（見三之一 ②）。
2. **實驗站的「課本規則」本來就在畫面上**：例如 Wi-Fi 訊號怎麼算、IPv6 怎麼縮寫、條碼怎麼讀 —— 這些是要學的東西，前端也拿來畫熱度圖、進度條。會寫程式的學生可以照規則自己算，但那等於真的學會了。
3. **Python 的程式碼在學生電腦上跑**：伺服器只看輸出。學生可以在主控台直接「印出」看起來對的輸出送上去 —— 但他得先知道預期輸出是什麼（伺服器不給），而且老師看得到最後一次送出的程式碼（`record.code`）。
4. **localStorage 的星星還是能改**：但改出來的星星**沒有伺服器收據**（或收據對不上），教師端驗證時會露出來。
5. **使用者腳本**：腳本可以替學生自動點按鈕，但拿不到答案，只能照規則算或硬試（同 1、2）。對策見三之一。
6. **單元一的 🧪 實驗任務**（x1～x4，共 12⭐）：任務是「動手調參數」，由網頁判斷是否達成，星星沒有收據。快速檢核（u1～u4）已改由伺服器發星。
7. **Git 歷史**：改成封存（2026-09）之前推上 GitHub 的版本是明碼；舊歷史備份在 `private/舊歷史備份_含明碼_勿上傳.bundle`（不要上傳、不要刪）。

## 三之一、防使用者腳本、防 F12：三層對策（2026-09-27）

| 層 | 做法 | 效果 | 誰來做 |
|---|---|---|---|
| ① 管理面（最有效） | Google 管理控制台 → 裝置 → Chrome → 設定（套用到學生的機構單位）：<br>・`ExtensionInstallBlocklist` 設 `*`，`ExtensionInstallAllowlist` 只放行需要的擴充功能 → Tampermonkey 等裝不了<br>・`DeveloperToolsAvailability` 設 `2`（不允許）→ **F12／開發人員工具打不開**<br>・電腦教室的 Windows：用群組原則（Chrome ADMX 範本）設定同樣兩項 | 學生在學校電腦上根本跑不了腳本、打不開主控台 | 資訊組（需要 Google Workspace 管理員權限） |
| ② 伺服器端 | ✅ 已完成：答案、判斷、❤️、發星都在 Apps Script，星星附簽章收據。<br>之後（教師端）：`LOG_SHEET_ID` 記下每次過關（已支援），再加逐題紀錄；教師端標出**異常旗標**：平均答題秒數過短、整關零錯誤且秒數過短、非上課時段短時間大量過關、收據對不上 | 看不到答案；作弊的痕跡**會被看見** | 伺服器已完成；教師端待做 |
| ③ 評量設計 | 闖關星星當「練習／形成性評量」；計分用老師看得到的：🏁 課堂挑戰（小組當場作答）、🧾 單元學習卡、實作作品、紙本 | 就算想辦法拿了星星也拿不到真正的分數 | 老師 |

網頁本身還有：答太快（1.5 秒內）或連錯兩次會「冷靜 5 秒」—— 對簡單的自動連點有一點效果，但不是防護。

## 四、檢查工具

| 指令 | 檢查什麼 |

| `node tests/leak_scan.mjs` | 公開檔案（網站＋`server/` 程式）裡有沒有 private 的明碼（解說、提示、標準公式、參考程式…）；公開 content 有沒有答案欄位；網頁有沒有載入出題器或舊封存檔 |

| `node tests/test_offline.mjs` | 連不上伺服器 → 練習模式 |

## 五、老師要做的事

1. **備份 `private/`**（隨身碟＋雲端硬碟）。它不在 GitHub 上，電腦壞了就沒了。
2. 改題目 → 改 `private/` → `node tools/build.mjs` → `cd tests && npm test` → **更新 Apps Script**（打開 `private/伺服器一鍵貼上/一鍵複製.html` 複製全部、貼到 `程式碼.gs`，再「管理部署作業 → 編輯 → 新版本」）→ 推送網站。
3. 公開的 `content/*.js` 開頭有「⚠️ 自動產生」字樣，**不要直接改**。
4. 部署步驟見 [`server/README.md`](../server/README.md)。
